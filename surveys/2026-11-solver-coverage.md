# Solver coverage survey, November 2026

Six comparisons across 53 benchmark pages have a concrete question, an existing baseline and a released implementation. The largest change in computational cost is the shifted dense solve. The largest change in the accuracy question is adaptive tau-leaping on the diffusion random walk.

Coverage below counts solvers selected in Julia code blocks, including constructors passed through setup arrays and loops. Imports, commented examples and reference-only solves do not count as timed competitors. The two repository names resolve to the same benchmark tree, so the DiffEqBenchmarks comparison yields the same page inventory. [Surveyed revision](https://github.com/SciML/SciMLBenchmarks.jl/tree/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks) · [DiffEqBenchmarks.jl](https://github.com/SciML/DiffEqBenchmarks.jl)

## Ranked additions

1. **[LHLFactorization](https://github.com/SciML/SciMLBenchmarks.jl/issues/1980)** on [LinearSolve/CacheReuse.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/LinearSolve/CacheReuse.jmd). A fixed dense Jacobian needs one cubic reduction. Subsequent scalar shifts cost quadratic work. The cache page times new right-hand sides and changed matrix entries, which cannot show how many shifts repay the reduction. First released in [LinearSolve 5.12.0](https://github.com/SciML/LinearSolve.jl/blob/v5.12.0/src/LinearSolve.jl).
2. **[SimpleAdaptiveTauLeaping](https://github.com/SciML/SciMLBenchmarks.jl/issues/1981)** on [Jumps/Diffusion_CTRW.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/Jumps/Diffusion_CTRW.jmd). The diffusion page times individual exact events. Adaptive tau-leaping groups events, trading accuracy for runtime. A fast approximate trajectory alone says little about the value of that trade. First released in [JumpProcesses 9.32.0](https://github.com/SciML/JumpProcesses.jl/blob/v9.32.0/src/simple_regular_solve.jl).
3. **[SDC](https://github.com/SciML/SciMLBenchmarks.jl/issues/1982)** on [NonStiffODE/Pleiades_wpd.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/NonStiffODE/Pleiades_wpd.jmd). The Pleiades page compares embedded Runge–Kutta, extrapolation and Gauss–Legendre methods. Deferred correction can change accuracy through the number of correction sweeps on the same nodes. First released in [OrdinaryDiffEqSDC 1.0.0](https://github.com/SciML/OrdinaryDiffEq.jl/blob/OrdinaryDiffEqSDC-v1.0.0/lib/OrdinaryDiffEqSDC/src/algorithms.jl).
4. **[KantorovichHomotopy](https://github.com/SciML/SciMLBenchmarks.jl/issues/1983)** on [NonlinearProblem/homotopy_continuation.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/NonlinearProblem/homotopy_continuation.jmd). The homotopy page already grades endpoint roots. Contraction-based step selection can now be compared with effort-based step selection while keeping the nonlinear corrector fixed. First released in [NonlinearSolveBase 2.36.0](https://github.com/SciML/NonlinearSolve.jl/blob/NonlinearSolveBase-v2.36.0/lib/NonlinearSolveBase/src/kantorovich_homotopy.jl).
5. **[Rodas4PW](https://github.com/SciML/SciMLBenchmarks.jl/issues/1984)** on [StiffODE/Bruss.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/StiffODE/Bruss.jmd). The sparse Brusselator exercises Rodas5P, BDF and Krylov solves. A fourth-order Rosenbrock W-method makes it possible to measure whether fewer Jacobian builds offset extra steps on the same semidiscretization. First released in [OrdinaryDiffEqRosenbrock 2.3.0](https://github.com/SciML/OrdinaryDiffEq.jl/blob/OrdinaryDiffEqRosenbrock-v2.3.0/lib/OrdinaryDiffEqRosenbrock/src/algorithms.jl).
6. **[SimpleBFGS](https://github.com/SciML/SciMLBenchmarks.jl/issues/1985)** on [Optimization/2drosenbrock.jmd](https://github.com/SciML/SciMLBenchmarks.jl/blob/1e621f6dc17cf74daae3fbcc25e5c2013627e5f9/benchmarks/Optimization/2drosenbrock.jmd). On a two-parameter objective, solver overhead and termination behavior can dominate. The page times Optim BFGS, and the lightweight implementation solves for a stationary point using the gradient. First released in [SimpleOptimization 1.0.0](https://github.com/SciML/Optimization.jl/blob/SimpleOptimization-v1.0.0/lib/SimpleOptimization/src/SimpleOptimization.jl).
